# Approach A (2026-10-07): exact block bounds, intersection walk, sorted parallel build, prefetch

Measured first, so the design follows the data (`data_A_2026-10-07/`).

## A1. Exact block-max bound, drift-corrected

### Measurement

`skippability.txt`: 2.19M Wikipedia, 1.10.0 index. A block is skippable for a query when its
score bound is at or below the final top-k threshold. The probe's own BM25 ranking matched
pg_fts's ranked top-10 exactly for year, slovakia and film (`skip_check.py`).

| term | blocks | skippable at k=10, 1.10.0 bound | skippable, exact block max | at k=100, 1.10.0 / exact |
|---|---|---|---|---|
| year | 5,742 | 2,453 (43%) | 5,734 (99.9%) | 656 / 5,674 |
| film | 1,647 | 22 (1%) | 1,638 (99.5%) | 1 / 1,555 |
| also | 9,180 | 1,228 (13%) | 9,174 (99.9%) | 106 / 9,094 |
| united | 4,203 | 1,357 | 4,194 | 259 / 4,114 |
| states | 5,182 | 1,659 | 5,173 | 219 / 5,093 |
| hungary | 189 | 22 | 180 | 2 / 131 |
| slovakia | 85 | 12 | 77 | 2 / 39 |

The 1.10.0 bound pairs the block's max tf with its min doclen, which usually come from
different documents; the exact max is almost always far lower. That is why 1.9.0 had to give
up on WAND for common terms and score exhaustively.

Rejected: storing the (tf, doclen) Pareto frontier per block. Blocks have 5-9+ frontier
points (`pareto_size.txt`); capping at 4 points recovers only 2,632 of year's 5,734 blocks.

### Design (revised after `dleff_walk.txt`)

**No format change.** The header's `min_doclen` field is a length the reader plugs into
`w(max_tf, dl)`. The writer now stores the *effective* minimum length

    x = floor(T * min_i (dl_i / tf_i))        T = block max tf, dl_i as the scorer sees it

instead of `min_i dl_i`. `w(T, x) >= w(tf_i, dl_i)` for every posting and EVERY average
length: `w(tf, dl) = (k1+1) / (1 + (k1(1-b) + k1 b dl/a) / tf)` is decreasing in dl/tf and
increasing in tf, so the point (T, T*min(dl/tf)) dominates every posting at once, for all
a. The reader's quantization only lowers x further (sound). 0 violations measured over all
blocks of 7 terms; the existing reader code is unchanged, so old and new segments are read
the same way, old segments simply keep their looser bound until a merge rewrites them.
(Rejected: a float `bmax` per block -- grows `BM25BlockHdr`, and a bound tight at the
writer's avgdl alone was violated 68 times in 1.4M random checks at other avgdl.)

| term | k=10 postings scored, 1.10.0 bound | new bound, docid walk | **new bound, best-first** |
|---|---|---|---|
| year (735k) | 70.7% | 2.6% | **0.56%** |
| also (1.17M) | 90.2% | 15.4% | **3.1%** |
| united / states | 82% / 80% | 7.8% / 6.1% | **1.5% / 1.1%** |
| film (211k) | 99.2% | 31.7% | **9.8%** |
| slovakia (10.9k) | 94% | 81% | 55% |

(Simulated over the real postings, exact top-k verified in every case; not a pg_fts
timing.)

**Best-first single-term top-k.** Visit a term's blocks in descending bound order (the
block headers are read first: 24 bytes each, ~46 per page), decode a block only while its
bound can beat the current k-th score, stop at the first that cannot. Exact by
construction: every unvisited block's bound is <= the k-th score found. Replaces the
`dense_score_min_df` exhaustive path for single-term queries; the dense loop stays as the
reference oracle in tests.

## A2. Intersection traversal for AND and phrase

AND and phrase candidates must contain every term. Drive the traversal from the rarest
term, skip whole blocks of the others by docid range, and apply the per-block bound of the
sum of terms. Phrase adds the existing lazy positional gate on each surviving candidate.
Today phrase ranks the bag-of-words union (`united | states`, 1.2M postings); the
intersection is at most the rarer term's 538k, and with bounds most blocks are skipped.

## A3. Sorted parallel build

Workers scan and analyze their heap slice, emit (term, docid, tf, doclen, positions) runs
into a shared tuplesort (spilling as needed), and the leader merges once into a single
compact segment written in order. Removes the per-worker segment merge and most of
`fts_vacuum`'s rewrite. Precedent: nbtree and PG 18 GIN parallel builds.

### Read path with a ring buffer and prefetch

The heap scan uses `table_index_build_scan`, which already uses a BULKREAD strategy (a small
ring of buffers) so a build does not evict shared_buffers. Two additions:
- Index pages written by the build and read back by the final merge go through a
  `BAS_BULKREAD` ring as well, not the default strategy.
- The merge's reads of each input run are sequential and known in advance: issue
  `PrefetchBuffer` a window ahead (effective_io_concurrency) so the reads overlap the decode.

## A4. Prefetch where the next pages are known

- Posting-chain walks: a cursor knows its term's page chain only one link ahead (nextblk in
  the page opaque). Prefetch the next page when a block on the current page is decoded.
- Dictionary seek, sidecar reads, tombstone blobs: bounded small reads, one-ahead prefetch.
- Heap: ranked results are fetched by TID after scoring; prefetch the top-k candidates' heap
  blocks before the visibility loop.
Prefetch matters only when pages are not in shared_buffers; the warm-cache benchmark will
not show it. A cold-cache band is added to the benchmark so it is measured, not assumed.

## Gate

- Exactness: every ranked band equal to the dense exhaustive reference (single term), to the
  collect path (phrase), and to the heap `fts_bm25` reference (in-place upgrade), as before.
- Mixed-format index (old + new segments) exact.
- Mutants: a bound one ulp too low must fail a test.
- Rebench the four engines on the 1.10.0 rig and protocol, plus a cold-cache band.
